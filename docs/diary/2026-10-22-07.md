# Diary — 2026-10-22 (07)

## ContentSignature frame tracking and device lookup hoisting

Roadmap 0006 addressed unsound capture skips when moving a lens view over static content, and Roadmap 0004
noted redundant Metal device queries on unchanged dimensions.

### Lens frame in ContentSignature

`BackdropCaptureCoordinator.ContentSignature` previously evaluated only the content view's bounds, subview/sublayer
counts, and layer contents identity. Moving an effect view over a static backdrop left all four fields unchanged,
causing `performContentSiblingCapture` to skip hierarchy rasterization and retain the stale texture.

- Added `frameInContent: CGRect` (the effect view's bounds converted to content coordinates) to `ContentSignature`.
- Moving the lens over static content now alters the signature and triggers a fresh capture immediately.
- Maintained skip behavior when both content and lens position remain stationary.

Regression: `moving the effect view over static content invalidates the content signature`. Confirmed red before the
field was added, then green.

### Hoisting device check in ensureBridge

In `ensureBridge(width:height:)`, the dimension equality check `bridge != nil, width == bridgeWidth, height == bridgeHeight`
was hoisted above device lookup, eliminating redundant `MTLCreateSystemDefaultDevice()` calls and layer inspection on
every capture frame.
