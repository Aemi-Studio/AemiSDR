## System style fix

The old production code failed three assertions on the Duo: the light preset did not have its actual 30-point radius,
and thick/ultra-thin materials had identical radius and saturation. The reader now obtains the live effect's filters
through Abysm, checks finite nonnegative values, and caches successful recipes by style and appearance.
It no longer calls `settingsForStyle:`, whose constants are unrelated to UIBlurEffect.Style.

An additional test showed that setting override traits on an unattached effect view does not resolve the adaptive
`regular` style reliably: dark still yielded the light radius. Calling the checked `effectForUserInterfaceStyle:` first
fixes that. Light regular resolves to 30 points, dark regular to 20, on both tested runtimes.

This requires the iOS system-style API and named presets to be `@MainActor`. Callers constructing configurations away
from the main actor must await resolution there; custom configurations remain Sendable and nonisolated.
Modern materials include tonal-map filters this value type cannot express, so the API now documents a scalar
approximation rather than promising pixel-equivalent material rendering.
