# Diary — 2026-10-20 (08)

## Corner wedges and the outermost pixel row

The owner's requirement: where a rounded mask or blur has a hole inside, the corners out to their pointy end must be
filled. A device's rounded corners hide that area and a simulator screenshot looks fine either way, so it cannot be judged
by eye. Pinned instead by rendering the real kernels (roundedRect, roundedRectEase, superellipse, superellipseEase through
`MaskType.kernelDescriptor` and `CIKernelCache.maskContext`) and reading pixels.

| Claim | Probe | Verdict |
|---|---|---|
| Every pixel outside the shape is fully masked | all 200×300 pixels vs an independent CPU rounded-rect distance, radius 60, fade 16, four shapes | **CONFIRMED** before any change |
| Inverted swaps them (wedges clear, middle covered) | same | **CONFIRMED** |
| A radius larger than the shape is clamped and the extent corners stay masked | radius 500 on 160×100 | **CONFIRMED** |
| The outermost pixel row is fully masked | radius 0, fade 0/2/8/16, corners and edge midpoints | **REFUTED**: eased kernels 0.88 at fade 8, about 0.84 at fade 2, and 0.0 with a hard edge |

Cause: `dest.coord()` is a pixel centre, half a pixel inside the edge of a shape that fills its extent; the masks reach full
strength only at the edge. Fix: `kPixelCenterBias = 0.5` added to the signed distance in all four kernels. After it all 112
assertions pass. The hole's edge moves half a pixel outward, below anything visible.

Mutation: replacing `length(max(d, 0))` in `rounded_rect_sdf` with 0 (the hole then extends into the corners) fails 26
assertions, the corner pixel reading 0.0; the same for the superellipse path (`corner = 0`). Both restored, none left.

## Found while reading the kernels (not yet fixed)

- `MaskType.kernelDescriptor` passes exponent 2 to both superellipse kernels, so `.superellipseSquircle` and
  `.easedSuperellipseSquircle` draw ordinary circular corners. A continuous-curvature corner needs a larger exponent.
  Needs a measured target (what the system draws) before changing, so it is on the Liquid Glass fidelity list.
- The mask kernels return all four channels equal to alpha and the CGImage is 32 bits per pixel for a one-channel
  quantity; halving it needs a probe of what Core Animation's mask and the variable-blur filter accept.
