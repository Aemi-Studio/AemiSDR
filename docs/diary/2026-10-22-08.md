# Diary — 2026-10-22 (08)

## Private API safety, Abysm KVC migration and PrivateAPIPolicy kill-switch

Roadmaps 0001 and 0003 addressed remaining unguarded private KVC calls and the absence of a global kill-switch.

### Abysm KVC migration

Previously, `NSObject.requestedValues` and `VisualEffectUIView` accessed private keys via raw Cocoa
`value(forKeyPath:)` and `setValue(_:forKeyPath:)`. On a missing or renamed key, Objective-C raises
`NSUnknownKeyException`, which cannot be caught by Swift `do-catch` and terminates the process.

- Migrated `requestedValues` get and set to Abysm's `RuntimeObject(self).value(forKey:)` and `setValue(_:forKey:)`,
  which catch Objective-C runtime exceptions via CAbysm's `@try/@catch` bridge.
- Migrated all `VisualEffectUIView` KVC accessors (`colorTint`, `blurEffectValue`, `setBlurEffectValue`, `scaleHintKey`)
  to `RuntimeObject`.
- A missing or renamed key now evaluates safely to `nil` or logs a one-shot fault, avoiding crashes on OS updates.

Regression: `requestedValues get and set on plain NSObject returns nil without raising`.

### Public PrivateAPIPolicy kill-switch

- Introduced public `PrivateAPIPolicy` (`PrivateAPIPolicy.isEnabled: Bool`).
- When disabled, private layer classes (`CABackdropLayer`) degrade to `CALayer.self`, `VariableBlurUIView` skips
  private `CAFilter` construction, `VisualEffectUIView` skips custom blur creation and perform calls.
- Added live drift canary verifying that active private symbols resolve cleanly.

Regression: `disabling PrivateAPIPolicy suppresses private classes and filters`,
`canary: all expected private symbols resolve or are recorded`.
