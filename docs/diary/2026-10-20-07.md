# Diary — 2026-10-20 (07)

## Metal toolchain restored without the system downloader

Xcode 27.1 (27A9275) replaced 27.2 RC and shipped without the Metal compiler; every build failed with
"cannot execute tool 'metal'". `xcodebuild -downloadComponent MetalToolchain` produced zero-byte downloads across
three attempts and two user-run daemon restarts; mobileassetd logged "Download already started" against a wedged
nsurlsessiond task and never received a byte (0.01 MB/s measured on the interface). The cached 27.2 compiler asset was
purged by the failed-download metadata refresh, so nothing local matched the installed Xcode.

Direct fetch instead: the catalog (/tmp/dvt.plist, devimages-cdn index) gives the 27A266a asset URL, size and SHA-1.
aria2c fetched the 800 MiB .aar (~2.6 MiB/s; SHA-1 matched `a401fb84…` exactly). `aea decrypt` with the catalog's
ArchiveDecryptionKey produced the Apple Archive; `aa patch` against an empty source directory extracted the asset
bundle (Restore/022-20184-410.dmg + BuildManifest). `diskutil image attach` mounts it: it contains Metal.xctoolchain
with the real compiler (metal 32023.921, target air64-apple-darwin27.2.0).

`xcodebuild -importComponent` was attempted honestly and rejected: its ExportMetadata.plist format (recovered from
DVTDownloads reflection strings: assetId, downloadSizeBytes, unarchivedSizeBytes, buildUpdateVersion, isInternal,
assetType) was accepted and the bundle copied into ~/Library/Developer/DVTDownloads/Assets, but the final step queries
the MobileAsset download database — which only the broken system downloader can populate — and fails with
"Asset not downloaded for '27A266a'". No user-space path can complete the official import.

Working user-space install: copied Metal.xctoolchain (3.0 GB) to
~/Library/Developer/MetalToolchains/27A266a/Metal.xctoolchain, then inside XcodeDefault.xctoolchain created
usr/metal/current → the toolchain's usr/metal/32023 (the path the `metal` shim probes — traced with lldb), plus
usr/bin/metallib and metal-ar symlinks so `xcrun -find` resolves them. Verified: `xcrun metal --version`,
`xcrun metallib --version`, an iphonesimulator-SDKROOT compile, and the full AemiSDR test build.

Residual, stated honestly: `xcodebuild -showComponent MetalToolchain` still reports "uninstalled" (cosmetic);
the symlinks live inside XcodeDefault.xctoolchain, so the next Xcode update removes them; nothing self-updates.
After a reboot the system downloaders may recover — retry `xcodebuild -downloadComponent MetalToolchain` then
and remove the user-space install if it succeeds.

## Mask cache bounded by bytes (roadmap 0007)

The shared mask NSCache had countLimit 32 and no byte budget. Red test: four 2048×2048 RGBA masks retained 64 MiB
(bytesPerRow × height per image) — at screen size a count bound allows hundreds of MiB. Fix: totalCostLimit = 32 MiB
plus the backing-byte cost on every setObject. Green: the budget test holds and the macOS suite passes — 92 tests.
